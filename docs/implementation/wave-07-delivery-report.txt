C. Database migration schema diff backfill and recovery

Migration source: 20261108120000_wave07_inventory_purchasing. No SQL was applied.
Adds Item.kind GOODS/SERVICE with GOODS default and stockTracking=false; adds
Company.isSupplier=false. Existing stock, supplier, financial and quotation history
are not inferred from names or rewritten. Existing service catalog entries can be
explicitly reclassified without enabling stock.

Adds thirteen tables: warehouses, stock_positions, stock_movements,
stock_reservations, stock_operations, purchase_orders, purchase_order_lines,
goods_receipts, goods_receipt_lines, goods_receipt_returns, supplier_bills,
supplier_bill_lines and expenses. Adds Firm/User inverse relations and physical
reservations on the existing SalesOrderLine. No parallel Item, Company, sales
Invoice or customer-payment master was created.

DDL includes 37 foreign keys and 17 CHECK constraints. Same-firm composite links
cover warehouse/item positions, ledger corrections, order-line reservations,
supplier/PO lines, receipts, returns and bill matches. Actors retain User foreign
keys. Quantity and reservation columns use Decimal(18,3); stock values use
Decimal(30,6); supplier document totals use Decimal(24,3).

Unique stock event key: (firm_id, source_type, source_id, source_line_id, event_type).
Other unique keys cover firm/warehouse/item positions, warehouse codes, PO numbers,
command idempotency keys and firm/supplier/bill reference. Period/owner/status
indexes support scoped reads and reconciliation. Reservation state, signed stock
values, received/returned caps and service/non-stock classification have SQL checks.

Movement and projection updates commit together under the existing firm row lock.
The application exposes no posted-movement update/delete or balance-overwrite
operation. Correction commands append movements with original-source references.

Legacy order snapshots lacking stockTracking remain non-stock. New orders freeze
the catalog's explicit tracking configuration. No historic dispatch is replayed or
assigned an invented warehouse/cost. Opening stock requires an authorized,
reasoned adjustment or a new actual receipt.

Review/apply the DDL in a dedicated disposable MySQL database and generate a matching
Prisma client before runtime validation. Neither action was performed here. Before
use, an application rollback may leave additive unused schema intact. After any
posting, preserve source/ledger/financial records and use reviewed forward fixes;
do not drop populated tables or reverse quantities by editing ledger rows.

Operational choices under the user's delegation:
- Block negative on-hand/available quantities; no implicit negative-stock override.
- Use moving weighted-average inventory value in the configured firm currency,
  exclusive of supplier-declared tax. This is operational valuation, not a statutory
  accounting/ITC claim. Quantity scale is three; stock value scale is six; whole-item
  units still reject fractions. Warehouses must be chosen explicitly.
- Incoming purchase value is frozen PO quantity times net unit cost. Consumption
  and supplier returns use current moving average. Customer returns allocate the
  original dispatch cost cumulatively, including the final precision residual.
  Transfers preserve total quantity/value within one firm transaction.
- Matched bills retain their approved PO currency/rounding/tax snapshot. Mixed
  source policies or price/tax variances require separate/corrected documents.
  Warehouse, catalog, supplier and receipt reference choices support server search
  beyond the first bounded result page while retaining selected records.
- Only the already-configured no-tax or India GST adapter is accepted. Supplier
  tax treatment is explicit; there is no input-tax-credit eligibility decision,
  tax submission, tax-document certification or inferred new jurisdiction.
- Return/transfer records are operational traceability documents. Posted supplier
  matches must be corrected/voided before a conflicting return; consumed receipts
  cannot be cancelled into an invalid valuation. No statutory supplier credit note
  or customer credit note is automatically issued by stock returns.
- New optional features require explicit plan/role access. Service-only presets
  reject tracked inventory; legacy tenants are not automatically inventory-enabled.

NOT IMPLEMENTED / explicitly excluded: supplier payment lifecycle or live banking,
full AP/general ledger, manufacturing/BOM, FX inventory conversion, certified/legal
document issuance and unrelated CRM/automation expansion. These are not claimed
as completed features of the bounded operational implementation.
