B. Plan versus executed changes; complete file inventory for this batch

The traced startup/shutdown path stopped the worker only after HTTP closed and
had no readiness/drain flag, hard deadline or cleanup error handling. Database
probes could wait indefinitely and launch a query per concurrent request. The
request logger emitted raw URLs/referrers; several provider/audit/Prisma logs
could emit raw exception text. Export DELETE tombstoned before unlink, then its
normal live-row lookup made an unlink failure impossible to retry. Production
configuration accepted unusable origins and short/shared/example signing keys.

Implemented neutral lifecycle/probe/logging helpers at their existing boundaries,
updated all traced consumers, and kept domain effects in their original
transactions. Late review added code-owned route groups, safe SMTP diagnostics,
storage quota/audit rollback regression sources and a temporary test storage root.
No diagnostic logs or TODO placeholders were introduced. Operational events below
are intentional fixed production metadata. All verification sources are unrun.

observer is optional; old startOutboxWorker callers remain valid. REQUIRED audit
behavior is unchanged. Production startup deliberately rejects formerly accepted
unsafe configurations; development/test fixture secrets remain compatible.

payment history, private file references and durable event identities. Do not

G. Risks, assumptions, pending decisions and go/no-go

Recommendation: NO-GO for production release and Wave 10/11 acceptance. This is
reviewable source progress, not formal security/compliance/production certification.

Known risks/limits:
- All new/prior code is uncompiled/unexecuted in this work. New Wave 10 schema
  and generated-client/SQL compatibility still require explicit validation.
- Earlier-wave source scope and full composed journeys remain incomplete.
- Probe timeout bounds the caller, not the SQL driver; a pending query stays
  single-flight. Readiness removes traffic but does not restart a stalled worker.
- Deadline exit can interrupt pending HTTP/rendering/delivery; durable recovery
  and remote deduplication still need real failure/restart evidence.
- Worker freshness is local loop health. Application DEAD/RECONCILE outcomes,
  schedule-discovery failures, backlog age and provider state need separate alerts.
- Request/process counters reset on restart and require a collector. All latency,
  throughput, error budgets, alert thresholds and launch scale are unmeasured.
- Existing fixed module notices and external proxy/provider/browser logs require
  separate review; the new closed logger is not whole-platform leak certification.
- Production configuration now fails for non-HTTPS origins and weak/shared/example
  keys. Secret entropy and approved rotation/storage cannot be established by
  length checks. Existing JWT rotation is coordinated, without old-key overlap.
- File unlink failures leave physical bytes despite logical quota release. Retry
  needs the same authorized actor/job ID; tombstones are not in normal lists.
  Crashed preparation can leave orphan files; no retention deletion was invented.
- Real PDF/font/Office output, render concurrency, reverse-proxy/cluster limits,
  path/security scans, performance/a11y and disaster recovery remain unverified.
- India is the only newly supplied launch decision. No tax, privacy, certified
  filing, RPO/RTO, retention duration, enabled gateway or service promise is assumed.
