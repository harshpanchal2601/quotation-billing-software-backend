1. Probes and drain contract

All paths are under /api/v1/health and respond with Cache-Control: no-store.
GET / and /live: existing healthy envelope, independent of database and worker.
GET /database: 200 healthy or 503 generic unavailable; no connection details.
GET /ready: 200 only if not draining, DB probe succeeds and an enabled local
worker has completed a successful recent cycle. Otherwise 503 generic not_ready.
GET /worker: 200 healthy/disabled or 503 unavailable; no firm, queue IDs or data.
Disabled means this process is not configured to run a worker. It does not mean
that pending work elsewhere has been delivered or that a worker is required.

HEALTH_PROBE_TIMEOUT_MS defaults to 2000 (100..10000). The request wait is bounded;
the SQL driver operation is not canceled. Only one underlying probe is pending
per process, with a one-second settled-result cache. A pool/driver timeout must
also be configured and rehearsed at infrastructure level. Sustained failed
readiness should remove a node from routing without making the DB-dependent
probe its liveness restart condition.

WORKER_STALE_AFTER_MS defaults to 300000 (60000..3600000), and must exceed the
OUTBOX_POLL_INTERVAL_MS. A cycle that hangs eventually becomes stale, even if it
is marked in flight. A rejected cycle is immediately unhealthy until recovery.
Outbox processing can successfully record DEAD/RECONCILE and finish its cycle:
worker readiness proves loop activity, not successful business delivery. The
schedule discovery/retention sweep have separate failure events.

SIGINT/SIGTERM mark the process draining synchronously. New business requests on
existing connections receive generic 503, Retry-After: 1 and Connection: close.
Health probes remain reachable on connections that have not closed. The HTTP
listener stops accepting connections; idle connections close and the worker
stops claiming while existing HTTP/worker operations drain concurrently. Prisma
disconnect happens only after both drains succeed. Failures exit nonzero. The
SHUTDOWN_TIMEOUT_MS deadline (default 60000; 1000..300000) forces socket closure
and exit 1 if work or disconnect stalls; it does not declare that work rolled
back or external delivery was canceled. Existing durable lease recovery applies.
Repeated signals reuse the same shutdown. Startup listener/worker failure uses
the same nonzero cleanup path. There is no new cancellation/financial engine.

For a future deploy, set the orchestrator's termination allowance above the app
deadline plus routing propagation allowance. Rehearse long requests, keep-alive,
idle connections, PDF work, DB outage, in-flight events and duplicate signals.
Record exit codes, committed source events and retry results. Do not infer a
successful drain from a missing process alone.

2. Logs, process metrics and dashboard specification

finish/close is counted once. Aborted requests use status 499 as a log marker.
The route group plus local pattern may not expand nested/dynamic router mounts;
